Normal execution needs no ZIP or PDF.

Keep chat brief: one short start message when required, only necessary status or blocking user actions while working, then a short result with actual media counts. Keep download timing and transport evidence in the manifest; explain them only when requested.

Write 1688 results to the task workspace's `outputs/<offerId>/` and PDD results to `outputs/pdd-<goodsId>/`, not the installed cache. ## Collect

1. Use the connected Chrome DevTools provider's `list_pages` once when needed. Reuse the existing signed-in Chrome: select the matching product, or open the user URL in a new tab of that session. Take one compact snapshot to check the product or satisfy the provider's first-read prerequisite. Follow the exposed pageId/selection schema. Refresh page IDs if the user navigates or closes a tab; do not fight their navigation.
2. On missing connection retry once; if still absent, give the required `chrome://inspect/#remote-debugging` setup and Allow step. Stop relevant actions on login, CAPTCHA, permission or an explicit security block. Keep the existing profile and normal website controls.
3. Execute the full packaged extractor once: `work/extract-1688-assets.js` for 1688, `work/extract-pdd-assets.js` for PDD. The 1688 extractor supports old/new gallery/detail layouts and Shadow DOM. PDD uses the observed labelled gallery/detail images, real lazy sources and only local title/shop/price/attribute fields; excludes comments, avatars, other buyers and account tracking. Never scrape all page images, guess original URLs or strip image-transform/signature queries. Compare captured gallery coverage with visible thumbnails/counts. An empty warnings array is not proof of coverage. If a relevant gallery/detail/video remains unloaded, activate a normal visible loading control once and recapture. Empty video results do not establish that there is no video. A video already present in the DOM can be downloaded without waiting for browser playback.
4. Verify the product ID against the user URL, preserving long IDs as strings. Save `source.json` and create `商品描述.md` from actual product text: product, material/specifications, seller if visible, SKU-specific prices and MOQ, and meaningful unknowns. PDD returns `platform: pdd`, `goodsId`, compatible `offerId` and an account-free real canonical URL. Keep separate subsidy/group-buy and single-buy prices; do not treat the shown minimum as all SKU prices. Do not invent missing facts or export login storage, unrelated account data or other buyers.

## Download the original media

5. With Node 22.12+, run one retained process: `node "<plugin-root>/work/prepare-materials.mjs" "<output-dir>/source.json" "<workspace>/outputs" --serve`. It downloads, verifies, generates and serves the preview once, printing one ready record with counts, failures and stage timings. Four workers start videos first while downloading images concurrently; source numbering remains stable, and verified SHA256 caches use no network. Do not raise concurrency by default: the measured 8-worker sample was not faster. `ASSET_DOWNLOAD_CONCURRENCY` supports 1–12 only for a requested test. On Mac, videos use domestic direct transport; other platforms retain the ordinary downloader unless explicitly enabled. This is a per-process request path, not a system network change.
6. For a 1688 `cloud.video.taobao.com/play/...` redirect, use an already observed fresh media request when available: `get_network_request` provides the actual HTTPS MP4 CDN URL, retaining its complete query. Record `source.videoResolvedUrls` mapping the original video URL to this browser-observed CDN URL, keeping `source.videos` unchanged. This avoids a known failed redirect attempt. If download still fails, activate the visible retry/play control once to refresh an expired URL and rerun; matching images are cached. PDD direct video URLs already in the DOM normally need no extra player/network inspection.
7. The domestic helper discovers the physical interface and live AliDNS IPv4 answers, binds ordinary-user curl to that interface, and resolves approved asset hosts for each redirect hop. It validates TLS and keeps its errors/evidence. Do not hardcode a previously observed CDN IP, remove signature parameters, export cookies, use sudo, change system proxy/TUN/DNS/routes/current nodes, or silently fall back to another proxy path. `ASSET_DIRECT_INTERFACE` may specify the user's physical interface for this process; it is not a global setting.
8. Inspect exit status and `assets-manifest.json`; verify successful file sizes/hashes and original source identity. A failed detected MP4 remains incomplete work: use the available ordinary authenticated URL and direct transport to resolve it. If a real site/permission/security block prevents further authorized work, report the concrete required action; do not bypass it or label a partial result complete. MP4 container validation does not prove full decoding. No HLS/blob/DRM conversion.

## Show the copyable result in the sidebar

9. `prepare-materials --serve` already generates the preview and validates its media snapshot once. Do not run a separate preview generator, hash loop or download pass after a successful ready result. The preview has copy-text/copy-image controls, a native local MP4 player/download link and truthful warnings; it uses only successful media matching the current source. If media are already prepared and only reopening is needed, use `node "<plugin-root>/work/serve-preview.mjs" "<output-dir>"`.
10. Open the ready record's approved localhost URL in the right sidebar. Reuse an existing result tab where practical; mark it as a deliverable. The server is loopback-only, serves listed media and supports MP4 seeking. Use HTTP, not a `file://` automation target. If the approved preview action itself is blocked, stop and give a local file/media link with the limitation.
11. Do one compact read-only UI check for displayed counts, copy controls and the video's ready/error state, then give the short result. Do not click every copy button, re-test the package, benchmark, reinstall or publish the repo for each product link. Default final: actual image/video counts and that the sidebar is ready for copying. Only create ZIP/PDF when explicitly requested. `bash download-mac.sh source.json [output-root] --zip` retains optional ZIP packaging for either site.

## Existing providers and scope

Chrome DevTools may come from this plugin or an already-connected 1688 Sourcing Agent; reuse the functioning provider rather than installing a duplicate. Mac installation and existing Windows Chrome connectivity are different checks. On Windows use the Node downloader, but do not run the Mac installer or assume an unbundled Windows script exists. The restricted preview generator/server currently require macOS filesystem protection and explicitly reject Windows/Linux; deliver copyable text and local media links there and report that sidebar limitation.

If the user explicitly names OpenCLI, read `OPENCLI-HANDOFF.md` and its own installed skill first. `check-opencli-mac.sh` is only command/version inventory; this package does not claim an integrated OpenCLI extraction path. The in-app browser is a result viewer here, not a substitute for extracting the 1688 product. An explicit browser-tool block cannot be bypassed with another provider, raw CDP, a new task, or a recovery browser.

This workflow reads the selected product and saves local files. It does not authorize purchases, cart changes, seller messages, account changes, or uploading collected media/URLs to GitHub. Repository publication includes reusable code and instructions only.
